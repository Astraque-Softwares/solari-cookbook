---
title: diagnose
description: The primary workflow - observe first, then run only the cheapest useful next step.
---

```bash
flakelab diagnose [test] [options]
```

A test target begins with a bounded scan; `--report` begins with read-only blob-report
analysis. The command writes `.flakelab/runs/diagnose.json` atomically after every phase so
interrupted work can be resumed.

Diagnosis explains observed evidence *before* proposing cloud or AI work, and recommends the
next experiment with a bounded trial count, expected duration, required credentials, and an
estimated cost - or a clear statement that no estimate is available.

After an eligible interactive diagnosis with a clean bounded scan, FlakeLab first asks:

```text
Search locally for a causal trigger now? [Y/n]
```

Local discovery is provider-free. It screens one applicable fault family at a time and uses at
most 28 executions. Only after a trigger passes the matched 4/6/8-pair causal gate does FlakeLab
ask separately whether to use Solari and AI. It then asks for an approved application source file
when `--source` was not supplied. Source ranking follows local imports and repository structure;
multiple matches are numbered and support Tab completion. There is no unsafe source default:
pressing Enter cancels. FlakeLab checks `GROQ_API_KEY` and `SOLARI_API_KEY` only after those
approvals and before provider work. Missing keys can be pasted through hidden, run-once prompts.
Prompts are skipped in CI and whenever stdin or stderr is not attached to a terminal, so
automation cannot hang.

## Options

| Option | Default | Meaning |
| --- | --- | --- |
| `--report <blob-report>` | none | Start from existing CI evidence. |
| `--baseline <artifact>` | none | Compare report analysis with earlier evidence. |
| `--runs <number>` | `4` | Repetitions in the control scan. |
| `--discover` | off | Screen locally and confirm one causal trigger. |
| `--investigate` | off | Explicitly enable bounded Groq investigation. |
| `--repair` | off | Explicitly enable candidate generation and Solari proof. |
| `--source <file>` | none | Approve an application source file; repeat up to seven times. |
| `--artifacts <dir>` | `.flakelab/runs` | Root for all default diagnosis artifacts. |
| `--evidence <path>` | `<artifacts>/investigation.json` | Investigation artifact. |
| `--reproducer <path>` | `<artifacts>/reproducer.yaml` | Shared discovery output and proof-pipeline reproducer. |
| `--patch <path>` | `<artifacts>/candidate.diff` | Candidate diff. |
| `--proof <path>` | `<artifacts>/proof.json` | Proof matrix. |
| `--html <path>` | `<artifacts>/report.html` | Portable report. |
| `--open` | off | Open the generated report without prompting. |
| `--model <name>` | `qwen/qwen3.8-27b` | Groq model identifier. |
| `--max-cost <usd>` | `0.25` | Model spend ceiling checked before work starts. |
| `--prompt-credentials` | off | Re-enter required keys through hidden prompts. |

Diagnosis also accepts experiment bounds: `--trials`, `--concurrency`, `--seed`,
`--max-delay`, `--min-rate`, `--pattern`, `--max-seconds`, `--max-steps`,
`--max-experiments`, and `--max-trials`.

## Provider phases are opt-in

Nothing chargeable happens without explicit approval. Flags provide that approval in
non-interactive workflows: `--investigate` enables Groq, while `--repair` enables Groq plus
one disposable Solari microVM. In an interactive diagnosis, answering yes to the Solari
handoff and the separate AI question provides the same explicit approval. FlakeLab prints its
credential and cost boundary and preflights both credentials before lengthy work begins.

## Examples

```bash
# Local only
flakelab diagnose tests/checkout.spec.ts

# Start from CI evidence
flakelab diagnose --report ./blob-report --baseline previous.json

# Local control scan, then confirm a trigger
flakelab diagnose tests/checkout.spec.ts --discover
```

<Callout type="info">
When diagnosis starts from `--report`, provide a test target before requesting experiments.
FlakeLab will not guess what to execute.
</Callout>
