Everything on this page is local and free until the final step, which is clearly marked.

The final provider-backed journey requires both `GROQ_API_KEY` and `SOLARI_API_KEY`. You may enter
them through hidden one-run prompts, a terminal environment, a local ignored `.env`, or protected
CI secrets. See [Provider credentials](/docs/credentials) before the first proof run.

<Callout type="info">
Want a complete repository instead of adapting these commands to your own project? Clone the
[FlakeLab Actual Budget demo](https://github.com/kelvinguchu/flakelab-actual-budget-demo). It is

</Callout>

## 1. Check the environment

```bash
npx flakelab@latest doctor
```

`doctor` verifies Node.js, your Playwright configuration, Chromium availability, whether
evidence paths are Git-ignored, and which provider credentials are present. It reports
*whether* a credential exists and where it came from - never its value.

## 2. Observe the test

```bash
npx flakelab@latest diagnose tests/checkout.spec.ts
```

This runs a bounded scan with retries disabled and classifies every selected test. It writes
`.flakelab/runs/diagnose.json` and prints the cheapest useful next step.

In an interactive terminal, an eligible diagnosis always ends with:

```text
Use Solari to prove a candidate fix? [y/N]
```

Press Enter to stop after the free local diagnosis. Answer `y` to approve the Solari
handoff. FlakeLab then separately asks whether AI may investigate and generate the candidate.
After both approvals, FlakeLab follows the selected test's local imports and suggests likely
application sources when `--source` was not supplied. Approve a single match, or select from
numbered, Tab-completable paths when several are found. The test file is never approved by
default. FlakeLab then compares the measured discovery estimate with `--max-seconds`, offers a
raised limit with headroom when needed, checks both provider credentials, and starts the bounded
proof pipeline. CI and piped commands never pause for these prompts.

Exit codes: `0` when no failure was observed, `1` for mixed or consistently failing
outcomes, and `2` when infrastructure makes the sample inconclusive.

<Callout type="info">
"No failure observed" means only that the bounded sample passed. FlakeLab reports an upper
confidence bound for the unobserved failure rate rather than claiming stability.
</Callout>

## 3. Search for a causal trigger

```bash
npx flakelab@latest discover tests/checkout.spec.ts \
  --fault network-delay \
  --pattern "**/api/checkout"
```

Automatic discovery screens only the applicable fault families, stops at the first causal signal,
then alternates matched-seed control and intervention trials, minimizes the fault boundary, and
independently confirms the result. Its reproducer and JSON discovery sidecar are written under
`.flakelab/runs` by default.

Pick the fault family that matches your suspicion - see the [fault catalog](/docs/faults).

## 4. Verify the reproducer

```bash
npx flakelab@latest replay .flakelab/runs/reproducer.yaml
```

Replay re-executes the exact saved fault set and checks that the recorded normalized failure
signature still appears. This is the artifact you can commit, share, or hand to a colleague.

## 5. Prove a fix

<Callout type="warn">
This step uses Groq and disposable Solari resources. FlakeLab announces the cost and
credential boundary before the first chargeable operation.
</Callout>

```bash
npx flakelab@latest prove tests/checkout.spec.ts \
  --source src/checkout.ts \
  --open
```

`prove` runs discovery, replay, investigation, repair, and reporting as one bounded
pipeline. The candidate is returned as `.flakelab/runs/candidate.diff` and is **never** applied to your
local checkout. To keep the reproducer somewhere else, pass
`--reproducer .flakelab/runs/checkout.repro.yaml`; the complete pipeline uses that same path.

## What you end up with

| Artifact | Purpose |
| --- | --- |
| `.flakelab/runs/reproducer.yaml` | Portable, strict fault and confirmation recipe. |
| `.flakelab/runs/investigation.json` | Hypotheses, experiments, and the bounded assessment. |
| `.flakelab/runs/candidate.diff` | A reviewable source patch. |
| `.flakelab/runs/proof.json` | Static checks, hostile trials, controls, and regressions. |
| `.flakelab/runs/report.html` | One self-contained offline evidence report. |

## If a run is interrupted

```bash
flakelab resume .flakelab/runs/diagnose.json
```

Resume validates the checkpoint and continues at the next safe phase without repeating a
completed scan, discovery, or investigation.
